# System Event Model

## Purpose Of This Document

This document defines the System Event Model for QFC-1. It identifies all external, timer, and internal stimuli that drive firmware behavior, establishes their classifications, and diagrams their propagation paths across the system.

The goal is to model what triggers the system to act before deciding on a runtime execution architecture.

## Why This Follows Object Decomposition

The previous document, [Object Model Decomposition](09-object-model-decomposition.md), defined the structural entities that make up QFC-1. However, structural models are static: they tell us who owns what, but they do not tell us **when** or **why** an entity executes.

To design an execution model, we must first catalog the stimuli (events) that arrive at object boundaries and trace how those stimuli flow through the system.

## What Constitutes An Event?

In real-time embedded systems, confusing an internal function call with an event is a common design error:
- An event is **NOT** a C function call (`foo_read()`).
- An event is **NOT** an internal variable assignment (`x = 5`).
- An event **IS** an observable stimulus arriving across a boundary that triggers a state transition, activates a pipeline stage, or signals a critical exception.

---

## Event Taxonomy

QFC-1 events fall into three distinct classes:

```text
[External Events (EXT)]  --> Stimuli arriving from outside the firmware boundary
[Timer Events (TMR)]     --> Cyclic triggers generated by hardware timer peripherals
[Internal Events (INT)]  --> Lifecycle, pipeline, and exception signals produced internally
```

---

## Complete Event Catalog

### 1. External Events (`EXT`)
| Event ID | Event Identifier | Source | Nature | Description & System Reaction |
| :--- | :--- | :--- | :--- | :--- |
| **`EXT-01`** | `SystemPowerOn` | Operator / Supply | One-time, non-periodic | Power applied or hardware reset. Triggers `FlightController.startup()`. |
| **`EXT-02`** | `ArmCommand` | Developer / Operator | Aperiodic, deliberate | Operator requests motor output. Valid **only** in `DISARMED`; ignored in `ARMED` or `FAULT`. |
| **`EXT-03`** | `DisarmCommand` | Developer / Operator | Aperiodic, deliberate | Operator requests motor suppression. Valid **only** in `ARMED`; returns state to `DISARMED`. |
| **`EXT-04`** | `IMUSampleReady` | MPU6050 (DRDY/I2C) | Periodic (1000 Hz) | New raw sensor measurements available in MPU6050 FIFO/data registers. |
| **`EXT-05`** | `IMUCommError` | I2C Bus Hardware | Aperiodic, fault | Bus timeout, NACK, or collision during read/write. Causes immediate transition to `FAULT`. |

### 2. Timer Events (`TMR`)
| Event ID | Event Identifier | Source | Nature | Description & System Reaction |
| :--- | :--- | :--- | :--- | :--- |
| **`TMR-01`** | `ControlLoopTick` | HAL Hardware Timer | Periodic (1000 Hz, 1 ms) | The heartbeat of QFC-1. Drives the sequential execution of the 1 ms control pipeline. Never skipped, never delayed. |

### 3. Internal Events (`INT`)
| Event ID | Event Identifier | Source | Nature | Description & System Reaction |
| :--- | :--- | :--- | :--- | :--- |
| **`INT-01`** | `IMUInitComplete` | `IMUDriver` | One-time, startup | MPU6050 configuration and `WHO_AM_I` check succeeded. Triggers `GyroCalibrator`. |
| **`INT-02`** | `IMUInitFailed` | `IMUDriver` | One-time, startup | `WHO_AM_I` mismatch or I2C failure on boot. Causes immediate transition to `FAULT`. |
| **`INT-03`** | `CalibrationComplete`| `GyroCalibrator` | One-time, startup | Gyro bias averaged and stored. Signals `SystemStateManager` to enter `DISARMED`. |
| **`INT-04`** | `CalibrationFailed` | `GyroCalibrator` | One-time, startup | Gyro variance exceeded resting noise limits. Causes immediate transition to `FAULT`. |
| **`INT-05`** | `SensorDataAcquired` | `IMUDriver` | Periodic (1000 Hz) | Raw counts converted to calibrated $\text{m/s}^2$ and $\text{deg/s}$. Dispatched to `AttitudeEstimator`. |
| **`INT-06`** | `AttitudeEstimated` | `AttitudeEstimator` | Periodic (1000 Hz) | Fused roll and pitch angles ready. Dispatched to `PIDController`. |
| **`INT-07`** | `CorrectionComputed` | `PIDController` | Periodic (1000 Hz) | Roll and pitch dynamic torque demands ready. Dispatched to `MotorMixer`. |
| **`INT-08`** | `MotorCommandsReady` | `MotorMixer` | Periodic (1000 Hz) | 4 clamped motor throttle values calculated. Delivered to `SystemStateManager` gate. |
| **`INT-09`** | `EstimatorDivergence`| `AttitudeEstimator` | Aperiodic, fault | Roll or Pitch angle estimate exceeds $\pm 90^\circ$. Causes immediate transition to `FAULT`. |
| **`INT-10`**| `MotorBoundsViolation`| `MotorMixer` | Aperiodic, fault | Pre-clamp command violated physical sanity bounds. Causes immediate transition to `FAULT`. |
| **`INT-11`**| `FaultDetected` | `SystemStateManager`| Aperiodic, broadcast | System transitioned to `FAULT`. Broadcasts to `PWMDriver` to zero all 4 channels instantly. |

## Event Flow Sequences

### 1. Startup Flow (One-time, triggered by `EXT-01`)
```text
SystemPowerOn (EXT-01)
  │
  └──> FlightController.startup()
         │
         ├──> IMUDriver.init()
         │      ├── SUCCESS ────> [INT-01: IMUInitComplete]
         │      │                   │
         │      │                   └──> GyroCalibrator.run()
         │      │                          ├── SUCCESS ───> [INT-03: CalibrationComplete]
         │      │                          │                  │
         │      │                          │                  └──> SystemStateManager.enter(DISARMED)
         │      │                          │
         │      │                          └── FAILURE ───> [INT-04: CalibrationFailed]
         │      │                                             │
         │      │                                             └──> SystemStateManager.enter(FAULT)
         │      │
         │      └── FAILURE ────> [INT-02: IMUInitFailed]
         │                          │
         │                          └──> SystemStateManager.enter(FAULT)
         │
         └──> Enter Normal Super Loop
```

### 2. Normal Control Loop Flow (Periodic, triggered by `TMR-01` every 1 ms)
```text
TMR-01: ControlLoopTick (1ms Timer Interrupt)
  │
  └──> FlightController sequences pipeline:
         │
         ├─ [1] IMUDriver.read()
         │      Consumes EXT-04 (IMUSampleReady)
         │      Produces [INT-05: SensorDataAcquired]
         │      (On bus error: produces EXT-05 -> SystemStateManager -> FAULT)
         │
         ├─ [2] AttitudeEstimator.update()
         │      Consumes INT-05
         │      Produces [INT-06: AttitudeEstimated]
         │      (On divergence: produces INT-09 -> SystemStateManager -> FAULT)
         │
         ├─ [3] PIDController.compute()
         │      Consumes INT-06 and Setpoint
         │      Produces [INT-07: CorrectionComputed]
         │
         ├─ [4] MotorMixer.mix()
         │      Consumes INT-07
         │      Produces [INT-08: MotorCommandsReady]
         │      (On bounds violation: produces INT-10 -> SystemStateManager -> FAULT)
         │
         ├─ [5] SystemStateManager.gate()
         │      Consumes INT-08
         │      ├── State == ARMED    ──> Pass motor commands to PWMDriver
         │      └── State == DISARMED ──> Suppress commands (force 0.0)
         │
         └─ [6] PWMDriver.write()
                Writes 4 compare values to HAL timer registers
```

### 3. Emergency Fault Flow (Aperiodic, immediate transition from any state)
```text
[Triggering Fault Source]
  - EXT-05 (I2C Bus Error)
  - INT-02 (IMU Init Failed)
  - INT-04 (Gyro Calibration Failed)
  - INT-09 (Estimator Divergence > 90 deg)
  - INT-10 (Motor Pre-Clamp Bounds Violation)
        │
        v
  SystemStateManager
        │
        ├── Transition state: current_state = FAULT
        │
        ├── Broadcast event: [INT-11: FaultDetected]
        │         │
        │         v
        │     PWMDriver.zero_all()
        │         │
        │         └── Write 0 to all 4 PWM hardware channels via HAL
        │
        └── LATCH FAULT: Refuse all subsequent ArmCommand triggers
            (Hold state permanently until hardware power cycle)
```

## Architectural Insights from Event Modeling

1. **One Dominant Periodic Event**: `TMR-01` (1000 Hz) drives the entire normal runtime behavior. All other events are one-time startup rituals or rare exception signals.
2. **Synchronous Consumption**: Every pipeline event (`INT-05` through `INT-08`) is produced and consumed sequentially within the exact same millisecond. No event needs to wait in a queue.
3. **Synchronous Safety Interlock**: Fault events bypass all remaining stages and force actuation to zero within the exact tick they occur.
